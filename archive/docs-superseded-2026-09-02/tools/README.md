# Tools folder

Offline dataset builders, harvesters, gauntlets, gates, estimators, and a few manual Arena utilities. None is imported by the live runner. Map re-verified against every flag and path on 2026-09-02; the two untracked 2026-09-02 tools are documented as they stand.

- `README.md` is this folder map.
- `api.py` makes authenticated diagnostic GET requests to Arena paths only.
- `audit_foreign_play_data.py` summarizes a collector decision CSV before model fitting: family mixes, facing-a-bet fold rates, aggression frequencies, sizing, and suggested class weights. Read-only and offline.
- `reconcile_foreign_raw_data.py` compares each collection's cached inventory, downloaded replays, and derived CSV, then classifies every gap: inventoried replays with no body on disk, downloaded replays outside the CSV, and which of those actually hold an in-scope decision. It also re-verifies CSV checksums and cross-season key uniqueness. Read-only and offline; `--report` writes the JSON audit.
- `rebuild_foreign_corpus.py` completes a collection without rewriting it. `--fetch` resumes the missing public replay downloads; `--derive` writes a sibling `*.delta.csv` holding only the rows whose `(agent_id, table_id)` receipt pair the frozen CSV never received, using that file's exact header so the pair loads together without duplicates. `--agent-scope archive` also admits agent folders whose full paginated history is cached but whose manifest omitted them; agents holding only the old 50-hand sample are never added. `--dry-run` reports both phases and changes nothing.
- `evaluate_policies.py` runs the offline gauntlet: each policy against the calibrated archetypes and the permanent shover plus head-to-head duels, scored in BB/100 at arena-realistic 60bb depth by default (`--starting-stack`). Duels run **both seat orders per seed** and report each orientation plus the seat mean, because the first-listed policy carries a measured structural advantage (first measured at about +11.7 BB/100, later found inside the noise at +6.30 — `.handoff/archive/v6-v7-era/STATUS.md`; the seat swap stays regardless). Every arm reports **paired per-seed differences with sample SD, SE, and t**, and **ruin metrics** (busts per 100 hands, bust rate per session) that BB/100 alone cannot see. `--duel-seeds` oversamples duels independently of `--seeds`; `--output` writes the report as UTF-8 without a BOM. `--ablate-sizing` reruns a candidate's action head with heuristic sizing; `--hybrid-min-advantage` evaluates an in-distribution, confidence-gated correction layer. Run with `python -m tools.evaluate_policies`.
- `head_degeneracy_audit.py` measures how often a network head returns a **constant** -- its output bias, bit for bit -- over the stored journal's feature vectors. Architecture-independent by design: it tests head-OUTPUT constancy rather than tower pre-activations, so it stays measurable if a LayerNorm is added. **Refuses to report unless three controls hit answers forced by construction**: a zeroed `out_w` must read 100%, a forced-live tower 0%, and the same weights scored twice must agree. Breaks results down by head, street, and whether hero faced a price; `--head` picks the head (default `action_value` when present, else the widest). Read-only and offline.
- `dead_head_experiment.py` runs the degenerate-group retrain end to end -- three arms (`off` / `zero_weight` / size-matched `random`) x N seeds, sequentially because each run wants ~8 GiB of host RAM -- audits every artifact, and applies the decision rule **frozen before any run existed** in `artifacts/evaluations/dead-head-retrain-prereg-2026-08-27.md`. Thresholds are constants in the module, never recomputed from the data they judge. Six VOID gates, including a seed-variation check (five identical seeds would otherwise confirm with a zero-width CI) and a `min_spread` check (a head constant at a NON-bias value scores a perfect 0.00%). It trains and measures; it never promotes or deploys.
- `separation_probe.py` measures **canonical strength separation** -- mean hand strength when a policy aggresses minus when it folds -- on `vs-p3`, using the same `separation_report` and seed convention as `p3-gate-2026-08-16` so the numbers are comparable to the published ones. This is the metric the previous architecture was retired over and the one that means "less degenerate PLAYER"; head constancy is a property of the model and, measured 2026-08-28, does not transfer to play. Reference points: field **+0.386**, `candidate-v7-0001c` +0.170, `candidate-v8-0001` +0.110. Offline and seeded.
- `gate_ablation.py` ablates the three unmeasured live-path gate changes (the effective-stack risk cap, the effective-stack call gates, and `reveal_expense_equity_slope`) across `vs-p3`, `vs-median` and `vs-station`. Every arm is the **same artifact one gate edit apart** -- the gates are overridden on the constructed policy, because a learned artifact rebuilds its own gates from its manifest -- so a contrast is attributable to exactly one edit. Paired on shared seeds, with a null mirror (`live` under a second label) whose differences must be identically zero, and paired statistics on **both** BB/100 and ruin. Offline, seeded, and it never promotes or deploys.
- `gate_binding_audit.py` prices those same three changes against the **stored live journal** rather than a battery. `.arena-training.jsonl` records both denominators the argument is about, so the counterfactual is computed rather than simulated, on real decisions whose hand outcomes are also on record. Reports how often each edit changes a verdict and which hands it lands on; the money column is an **association, not a counterfactual saving**, since clipping a bet changes how the hand continues. Gate constants come from the incumbent's manifest, not the dataclass defaults. Read-only and offline.
- `promote_candidate.py` promotes a verified candidate to the approved live artifact (atomic `artifacts/approved.json` pointer) and rolls back (`--rollback`). Requires `--reason`; never contacts Arena. Since 2026-09-02 a **format-4 (v9) candidate must pass the OLS baseline gate** from `ols_baseline.py` — `--ols-gate {enforce,warn,skip}`, default `enforce`, where `skip` is an explicit, documented owner override — and `--evaluation-note` records the evaluation beside the reason. It enforces no gauntlet gate: the winner-only rule is a human discipline.
- `self_play_cycle.py` harvests a diverse diet from champion states by default (calibrated lineup, heads-up vs shover/station/nit, heads-up vs the card-aware `TexturedAgent` — `--textured-hands`, default 1,000, which ends vs-textured's held-out status in the batteries — and optional sparring; `--sparring champion --sparring-record-both` spars the built-in champion and records both seats; `--on-policy` makes the learner rather than the champion the hero). One decision per actor per hand is replayed across **every legal family through the acting policy's own serve path**, and `--counterfactual-rollouts` averages continuations that **re-deal every chance outcome the decision could not see**. A branch is emitted only where the engine **actually executes** it and where its executed `(action, amount)` differs from an already-emitted branch, so a group carries **2 to 4 branches**, not always four: a `fold` is a free check whenever check is legal, a forced `aggress` with no legal bet or raise falls through to a check, and the two aggression sizes merge once the risk cap or the `raiseRange` clamp collapses them. Each row records the absorption map so a consumer can find the branch holding the value of an action whose own label was dropped, and decisions reduced to a single executable action are dropped at the source. `--architecture v7` trains the format-2 two-branch network with the size-conditioned value head (CUDA only); `v6` keeps the frozen three-output path. `--examples-out` persists the assembled corpus (gzip float32 matrix plus a JSON sidecar) and `--examples-in` retrains from it without harvesting, which is what makes "same data, different recipe" experiments possible; `--split-seed` and `--init-seed` separate the validation split from weight initialization. `--device cuda --batch-size 256` moves vectorized fitting to CUDA while simulation stays on CPU. `--harvest-workers 0` (the default) runs the independent legs in one process each within the core count; every leg is separately seeded, so the examples and their order are identical either way and only wall-clock changes -- measured 2.47x on a four-leg harvest. `--dry-run` validates every corpus and prints the session without simulating or training.
- `build_preflop_percentiles.py` generates the fixed preflop percentile table behind the canonical strength metric (`.handoff/notes/V8_DESIGN.md` sec. 2): the percentile of each of the 169 canonical classes under a fixed heads-up all-in-equity ordering, combo-weighted (pairs 6, suited 4, offsuit 12; 1,326 total) with the mid-rank convention. It runs **once** and its output is committed as `engine/preflop_percentiles.py`, so live inference is a dict lookup with no per-decision simulation and no drift -- alone among these tools it writes into the package source rather than `artifacts/`. The same `--seed` (20260816) and `--trials` (20,000) reproduce that file byte for byte; **regenerating with different parameters is a metric change and therefore a schema event, not a patch.** Offline, reads no credentials, promotes and deploys nothing.
- `build_phase_a_dataset.py` builds the Phase-A supervised dataset (`.handoff/notes/V8_DESIGN.md` sec. 5) from the complete-information replay archive, whose replays reveal every seat's hole cards including folders, so the three composed-value heads have observable ground truth in real hands. One JSONL row per `ActionTaken` decision per seat: the full **schema-3 vector (413 floats)** under the neutral belief provider on the decision-time snapshot, plus labels with defined-masks -- `fold_through_small` / `fold_through_large` (one observed outcome shared by both branch labels, the mask recording which E6 branch the realized size matched), `range_bucket` (strength-percentile octile of the strongest holding among opponents who did **not** fold to the action), and `equity_called` (exact by enumeration when at most one board card remains, seeded Monte-Carlo `--equity-trials` -- default 500, ablatable -- preflop and flop). Event reconstruction is **imported from `collect_foreign_play_data`, not re-derived**, and `allowedActions` are not approximated: they come from the engine's own payload verbatim, and a decision lacking them is skipped and counted in the sidecar. `TimeoutAction` emits no row (it is not a decision the actor made) but its folds still drive the label windows. Per-row impossible-by-construction checks abort the run; the load-bearing one is that a `fold_through` of 1.0 requires the actor to appear in the replay's own settled `winners`. Deterministic: every stochastic quantity is seeded from `(seed, table_id, sequence)`, so rows are independent of worker count and file order, and the gzip mtime is zeroed so reruns are byte-identical. Offline and read-only over the archive; writes only under `artifacts/phase_a/`.
- `build_p3_dataset.py` fits the **P3 strength-aware opponent**, the precondition named in `.handoff/PLAYERS.md` ("What is missing, and what to build first"): every scripted archetype is card-blind, so none of them can punish a policy that bets a random hand, and every sizing and aggression conclusion this project has drawn was blocked on that. Two phases. **Dataset** -- one row per decision facing chips to call, carrying the actor's *true* holding as the canonical `strength_metric.strength_percentile` (the only strength scale this project reports on) alongside price, street, seat count, position and a board-texture proxy, labelled folded or not; replay parsing is imported from `collect_foreign_play_data` via `build_phase_a_dataset` rather than re-derived. **Fit** -- a pure-stdlib logistic regression by ridge-damped IRLS, deterministic with no sampling, shuffling or seeds anywhere; streets get their own model where the data supports one and are pooled where it does not, by a rule fixed **before the counts were looked at**, validated on a 20% hold-out split **by table** so no table contributes to both sides. Validity is decided by a sign invariant: the `strength_percentile` coefficient must be **negative** and the price coefficient **positive**, or the run stops without shipping -- enforced here, again at load in `strength_aware_opponent.P3Fit.from_document`, and again in the tests against the shipped JSON. Before it touches a replay it fits three impossible-by-construction cases (known coefficients must be recovered; inverting every label must flip every sign; labels independent of the features must give ~zero coefficients and AUC ~ 0.5) and refuses to continue unless all three come out right. `--fit-only` refits an existing dataset and `--selftest-only` runs just the instrument check. Read-only over the archive, writes only under `artifacts/p3/`; it opens no network socket, promotes and deploys nothing, and never touches `artifacts/approved.json`.
- `build_phase_b_corpus.py` generates the Phase-B counterfactual value corpus against the repaired P3 opponent (the 2026-08-16 price-support clamp). Branch labels are generated exactly as v7's were -- **one eligible decision per actor and hand**, `inclusion_count` recorded, forced branches through the acting policy's **own serve path** (`decide_forced`) -- but the actor is a v8 candidate and the branch set is the **E6 state-dependent** one: `fold`, `check_call`, and `aggress_small` / `aggress_large` only where a legal bet/raise range is stated, sized by the unclamped E6 target whose specs are shared with `feature_extract_v8` / `compose_branch_values` so label-time and serve-time sizing cannot drift. `table_simulator.py` is **subclassed, never edited**. The load-bearing addition is the chance-salt rule for a card-aware seat, because both stock behaviours are wrong for P3: frozen holes make every rollout share one opponent holding, so the label converges on E[chips given that holding] instead of Q(s, a), while free resampling contradicts the opponent's own committed actions. Hero's cards and the revealed board stay fixed, future board cards resample per rollout, and the P3 seat's holes **also resample per rollout, never frozen**, consistently with its own prefix -- the seat plays its original cards through the prefix replay so the betting history reproduces byte-for-byte, then its holes are replaced by a **rejection sample** accepted on the joint fitted probability of its observed prefix choices (`--p3-accept-threshold`, `--p3-resample-tries`). Exhausted draws fall back to a uniform resample and **the fallback rate is counted and reported per leg and in the corpus summary**. Documented approximation: the acceptance likelihood reads only the fitted fold probability, which is conservative when a shove fired before the fold roll and errs toward stronger holdings, never weaker. With no P3 seat present the arranged replay is **byte-identical** to the stock salted replay, which the tests assert as the validation of the replication. Output is a documented v8-native gzip-JSONL format under `artifacts/phase_b/` -- not `training_telemetry.save_training_corpus`, which hard-pins the v7 learning contract (schema 2, 142 features) that schema-3 rows cannot honestly claim; `--validate` runs the reference reader's checks (per-decision centered sum ~0, every label finite, every vector `schema3.require_vector`-clean, absorption map coherent) and `--dry-run` changes nothing. Pure offline simulation: no Arena requests, no credentials, no promotion.
- `build_phase_a_dataset_v9.py` is the **v9 sibling** of `build_phase_a_dataset.py`, which stays byte-untouched along with its stored dataset; the replay walking, label windows and determinism discipline are imported rather than re-derived. What changes is the v9 data contract, pinned in `.handoff/notes/V9_RESTRUCTURE_PLAN.md` and enforced by the trainer's own loader. The **renamed label keys are the version guard**: `fold_through_active` / `fold_through_aggressive`, plus `to_call_zero` and `read_temperature_x10` (g's read as the raw int `10*T`) on every row. Both directions are tested, because both schemas are 413 entries long, so the KEYS are the only thing separating them. The fold-through gate keys on **raw wager actions** `{bet, raise, all-in}` and never on a branch or family — the v9 `active` branch contains calls, which define no fold-through, and no validator would catch that mislabel — with the lane decided by state (free spot supervises the active lane's bet execution, a priced escalation the aggressive lane). One carve-out the v8 builder lacks: a **call-for-less all-in** at a price supervises neither lane and is counted (`allin_call_for_less`) rather than mislabeled, because it puts nobody to a decision and buys no folds. The **midpoint rule is deleted** — there are no fixed-size branches left to assign — and the realized size is recorded raw and normalized instead. Features are **schema 4 through the fitted P3 belief provider** (the same provider the v9 serve path defaults to, so the eight bucket inputs are live in training exactly as at serve; per-decision degrades are counted), and the vector's `equity_multiway` slot is asserted equal to the recorded read per row — one computation, two consumers, checked rather than assumed. The sidecar carries the **composed `sizing` record** the features were extracted under, which is what the trainer's `resolve_sizing_record` reads, so a training run's manifest describes the same g state the vectors baked. The build finishes by loading its own output through `engine.v9_trainer.load_phase_a_dataset_v9`: a dataset this tool blesses is one the trainer provably accepts. Offline and read-only over the archive; writes only under `artifacts/phase_a_v9/`.
- `build_phase_b_corpus_v9.py` is the **v9 sibling** of `build_phase_b_corpus.py`, which stays byte-untouched, and it inherits that module's harvest physics verbatim — the arranged-deck replay, the conditional P3 hole swap and its statistics, the hero snapshot recorder, and the one-selected-decision-per-actor-and-hand rule with its RNG. `table_simulator.py` needed **no edit at all**: the harvester subclass owns the whole branch layer. Candidates come from `branch_contract_v9.legal_branch_labels` on the captured snapshot, and `_E6_BRANCH_SPECS` dissolves into g — wager sizes are the **composed sizing** at the decision's recorded read, derived from the DECODED stored `10*T` int so the harvest derivation and the trainer's re-derivation are the same arithmetic on the same bits. **`ContractForcingRecorder` is the load-bearing piece**: forced `fatal` / `passive` / priced-`active` branches execute LITERAL fold / check / call payloads rather than routing through the policy's rails, because the v9 slots are semantic (each carries a fixed value formula) and the corpus has no absorption channel to record a substitution. Measured on the first smoke harvest, rail-routed forcing dropped **40 of 73** selected decisions — the call-margin gate folded 33 forced calls and the bluff mixer raised forced folds — biased against exactly the negative-EV call states the model needs fold-beats-call contrast on; contract forcing drops **7 of 73**. The two sized wager lanes still run through `decide_forced` (the g hand-off needs the engine's floors, rounding and risk cap). The **purity check** is the assertion of all this: a branch must execute its own contract action AND at the amount the row will record, since the action name alone admitted a cap-refused escalation executing as a shove while the constants still described the small raise — and the loader cannot catch that, because it re-derives the same composed number so its cross-check passes tautologically. Drops are counted per `branch->action` class and reported per leg and in the summary, alongside `belief_degrades` (rows whose belief buckets silently fell back to the uniform prior — the provider swallows its own errors per decision, and nothing outside the Phase-A builder counted them until 2026-08-30; the row still ships, but a material rate means the corpus trained on buckets the serve path would not reproduce). The header is `corpus_schema_version: 2` carrying the composed sizing record, `belief_fit_source`, `equity_trials` and the frozen-instrument fields; after writing, the corpus is reloaded through **the trainer's own `load_phase_b_corpus_v9`**, so its schema-2 gate, frozen-g re-derivation and emission-equals-legality all run before this tool blesses a harvest. `--validate` loads an existing corpus through that same reader. `--equity-trials` defaults to **1,000** (owner decision, 2026-08-30: harvest == serve, one number) and propagates to the served model through the corpus header and the manifest's `serve.equity_trials` pin. Two modes were added on 2026-08-31 for the street-balanced corpus: `--postflop` switches selection to one point per reached postflop street under per-street quotas (`--street-targets`, default `15000,10000,6000`) instead of the uniform one-per-hand rule, and `--merge BASE EXTRA` combines two corpora after loading both through the trainer's reader, refusing incompatible headers and overlapping leg seeds. Pure offline simulation: no Arena requests, no credentials, no promotion.
- `evaluate_v8.py` gauntlets a **format-3 (v8) candidate, or with `--candidate-v9` a format-4 (v9) one**, through the frozen instrument. `--candidate-v9` (2026-09-01) switches the whole run to the v9 contract — the `V9PolicySpec` built through `learned_policy_v9.load_policy_v9`, `--floors v9` by default, the v9 branch-contract fragment stamps, the v9 study name; `--floors {v8,v9,both}` picks the floor set, the v9 one being `always_fatal` / `always_passive` / `always_active` / `always_aggressive` plus `uniform_random_legal`, with the sized lanes running g at the neutral read; `--stages`, `--p3-fit`, `--p3-seeds` and `--null-scale` are the other additions. Every fragment carries `branch_contract`, and assembly refuses mixed contracts. It is an additive wrapper -- seat-swapped duels, paired per-seed t statistics, battery construction and ruin denominators are imported from `evaluate_policies` unchanged -- adding only what the v7 tool cannot field: a policy spec that builds through `learned_policy_v8.load_policy_v8`; the **v8 trivial-baseline floor** (`always_fold`, `always_check_call`, `always_aggress_small`, `always_aggress_large`, `uniform_random_legal`) run through the *same* battery channels, seeds and session mode as the candidate, so floor and candidate are scored by one instrument, with the aggress baselines sized at the E6 stack-aware branch targets and `always_fold` following the v7 absorption convention (a fold the table would give away for free is played as the free check, which is what the engine would execute); per-street strength separation (`.handoff/DECISIONS.md` sec. 5) on the canonical metric from a dedicated recording simulation; and a **self-duel null check** whose paired differences must be identically zero, validating the task wiring before any real number is read. Every stage writes its fragment to `--workdir` as soon as it completes and the final report is assembled from whichever fragments exist, so a crashed or skipped stage never throws away finished compute. Record `--starting-stack` (default 6,000), `--equity-trials` (80) and `--scale` with the result; a battery is only comparable to another run at the same config. Entirely offline; no Arena requests, no promotion, and `artifacts/approved.json` is never read or written.
- `p3_gate.py` is the held-out **P3 gate**, the first battery seat that can see its own cards. `.handoff/PLAYERS.md` and `.handoff/notes/V8_DESIGN.md` sec. 6.7 are explicit that the strength-aware opponent enters the batteries **as a gate, before any training uses it**. Six real arms plus a wiring mirror, on identical seeds and identical hand counts, over three channels: `vs-p3`, the fitted `StrengthAwareAgent`; `vs-median`, the **structural twin control** with the same aggression, the same nominal `fold_vs_bet` and the same seeds, differing only in that its folding is a constant instead of the fit, so a vs-p3 minus vs-median difference is attributable to exactly one edit; and `vs-station`, the channel the candidate broke worst on (-332 BB/100 against the champion) and the archetype the diagnosed mechanism blames. `noise-floor-2026-08-15.json` publishes no `vs-p3` row, so any number read off that channel against a published figure would be uninterpretable; two MDEs are therefore derived from this run's own data -- an independent-seed `2*sigma/sqrt(n)` reproducing the published construction exactly (checked against the published vs-median row), and a much tighter paired `2*sd(diffs)/sqrt(n)` on per-seed differences, which is the instrument the contrasts here actually use because every arm plays the same cards in the same order. **Anything below the relevant MDE is UNRESOLVED, never a win and never a loss.** The `instrument` stage runs first and is reported first: the opponent's own canonical strength when it continues minus when it folds must be ~0 for the card-blind `vs-median` seat -- impossible by construction to be anything else, since that agent never sees a card -- and clearly positive for `vs-p3`, or the fit is not reaching the table; plus a self-null arm whose paired differences must be identically zero, chip conservation on every match, and a deterministic monotonicity sweep of the fitted fold probability. The P3 seats run as `evaluate_v8.StrictStrengthAwareAgent`, which **raises rather than silently degrading to the card-blind constant**, so no vs-p3 number in the report can have been partly produced by a different opponent. Stdlib-only, entirely offline, seeded throughout; it trains, harvests, promotes and deploys nothing, and never touches `artifacts/approved.json`.
- `measure_field_separation.py` recomputes the **field strength-separation benchmark** on the canonical metric. `.handoff/notes/V8_DESIGN.md` sec. 2 requires this before any v8 number is compared to the frozen +0.150 field / +0.020 us pair, which was measured on a different, undocumented percentile-style scale -- sec. 1c showed two scales in circulation disagreeing 3x on the same decisions. It walks the complete-information archives and, for every `ActionTaken` decision by every seat, computes the `strength_percentile` of the actor's **real revealed** holding on the **decision-time** board and the canonical `training_telemetry.action_family`, then reports per street and overall, with seeded bootstrap-over-hands 95% CIs: separation exactly as the frozen report defined it (mean strength when aggressing minus mean strength when folding) for the field, the same per agent for the leaderboard top-15, our own agent on the same instrument, and action-mix context (fold / check-call / aggress rates per street and the median bet as a fraction of the pot). The scope conventions reproduce the frozen report rather than improve on it: **"field" excludes our own agent** -- the frozen table is "S14 field vs `candidate-v7-0001c`", and pooling our decisions in would move the very quantity the gate checks, though `all_agents` is reported too -- **`TimeoutAction` is not a decision**, and excluding it is what reproduces the published 55.8% / 21.5% (including them gives 58.6% / 20.5%), and one replay file is one hand, so the bootstrap resamples tables. Two reconstruction details are deliberately not taken from the snapshot: the decision-time board is rebuilt from `StreetDealt` payloads, because the snapshot is captured *after* the action and on **962 of 9,084 decisions (10.6%)** already carries the next street's cards, so reading strength off it is forward-looking leakage; and bet size uses the engine's own `(new chips - call) / (pot + call)` pot fraction, the quantity the frozen "median bet 0.60x pot" is on (the earlier 1.333x figure double-counted the call). Two gates run before any separation number is presented -- a **reproduction gate** against the published S14 behavioural rates within 2pp, computed on the S14 collection alone since that is the window they were measured on, and an **impossible-by-construction gate** in which a seeded control holding drawn from deck-minus-board must separate indistinguishably from zero, because a pipeline that finds separation on cards the agent was never dealt is measuring itself -- plus per-decision structural invariants whose violation aborts the run. Offline, read-only over the archive, stdlib-only, fully seeded; writes only its JSON report and an optional `--markdown` summary.
- `summarize_seed_spread.py` assembles the three-seed spread report from finished `evaluate_v8` reports. It is additive and **runs no simulations**, re-deriving every number from the per-seed fragments, so it cannot invent a result the gauntlets did not produce. The deliverable is the **training-init-seed spread**: max minus min duel margin against `candidate-v7-0001c` across the init seeds, set against the 16.78 BB/100 figure from the v7-0002 corpus -- exactly the same quantity, max minus min duel margin across three init seeds of one corpus on this instrument (v7-0002a -7.06, b -1.88, c +9.72), so the comparison is like for like. Because every gauntlet duels on the same evaluation seeds against the same incumbent, the per-seed margins are paired by common random numbers, and the report carries both readings: the raw spread of the three means (the requested deliverable) and **paired per-evaluation-seed contrasts** between init seeds, which remove the shared evaluation noise and are the more sensitive test of whether the init seeds differ at all. Takes `--gauntlet <init-seed>=<report path>` once per gauntlet and writes combined JSON plus Markdown; offline, reads no credentials, promotes and deploys nothing.

On 2026-09-02 a 2-parameter OLS beat the v9 net on its own corpus (`artifacts/evaluations/v9-loses-to-v7-diagnosis-2026-09-02.md`). - `collect_foreign_play_data.py` scrapes public Arena replays into `foreign play data/`. **Needs no credentials** (public endpoints, no auth), is globally throttled to ~8 req/s with `Retry-After` handling, and takes `--arena <slug>` plus season and bounding flags. Replays reveal every seat's hole cards, including players who folded.
- `leave.py` asks Arena to remove the agent from the explicitly named competition; importing it has no side effects.
- `peek.py` prints the explicitly named competition's pending-action state; importing it has no side effects.
- `poll.py` waits for a sandbox submission and returns a failure code unless it succeeds.
- `submit.py` uploads a strategy file or bundle to a sandbox competition.
- `update_agent_profile.py` renames the agent and refreshes its public profile through `PATCH /agent/me`. Dry-run unless `--apply`; the public quote and description default to the owner-mandated `Hello`. After a PATCH it verifies **per field**, because an endpoint that ignores an unknown key still answers HTTP 200. **The public handle cannot be changed through this endpoint**: measured 2026-08-26, sending `handle` returns `HTTP 400 "body must not have additional properties"` and the whole body is discarded, so the display name and the handle can and do diverge (`0Fold` vs `@fold_ver_3`).

Arena-facing tools resolve credentials from `ARENA_CREDENTIALS` when it is set, otherwise from the repository's gitignored `.arena-credentials`, so routine commands need no environment setup. **This was only true of `api.py` and `update_agent_profile.py` until 2026-08-28**: `leave.py`, `peek.py`, `poll.py` and `submit.py` each required the environment variable and exited without it — including `python -m tools.leave`, which `.handoff/DECISIONS.md` §1 names as the *only* recovery when a stop fails to release the seat and there is no unclaim endpoint. All four now mirror `api.py`'s resolution — each carries its own copy of it, and only `update_agent_profile.py` imports `api.py`, so there are five copies to keep in sync.
