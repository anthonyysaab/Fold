# Artifacts folder

This folder contains trained data read by policy code.

- `README.md` is this folder map.
- `tiny-policy-pure.json` is the legacy 125-input, 64-hidden-unit, 3-output network. The live policy loads and validates it, but this export has no `table_sizes` metadata, so it does not currently choose live actions.
- `candidates/` holds multi-head candidate artifacts: a validated manifest plus a checksummed JSON weights file per version, written by the offline trainer and readable by `learned_policy.py`. Format 1 ("v6") keeps the fixed three-output shape and records `counterfactual_value` semantics. Format 2 ("v7") is manifest-driven: the architecture descriptor carries the card/context index split, encoder and trunk widths, and four heads, so a shape change is a manifest change rather than a code change. Both formats load; only format 2 pins aggression to an executable pot fraction and records trivial baselines plus a margin-quantile map for the hybrid gate.
- `corpora/` holds persisted harvest corpora (gzip float32 feature matrix plus a JSON sidecar) written by `--examples-out`. It is gitignored: a corpus is hundreds of megabytes and is reproducible from its recipe. Reusing one via `--examples-in` is what makes a training change isolable from a data change.
- `training-runs/` holds immutable launch recipes and logs. `candidate-v7-0001.ps1` is the current recipe: 48,000 hands, salted two-rollout counterfactuals, champion sparring with both seats recorded, then three init seeds trained from one persisted corpus. It does nothing unless called with `-DryRun`, `-Start`, or `-RetrainOnly`.
- `approved.json`, when present, is the atomic pointer to the approved live artifact, written only by `tools/promote_candidate.py` after the evaluation gate. `run_agent.py --learned` follows it and refreshes between hands. It currently points at `candidate-v7-0001c`, the first learned artifact ever promoted here (2026-08-14). `manifest_file` is always written with POSIX separators so a pointer promoted on Windows resolves on the Linux live host.
